# MERIDIAN — Phase 1: Data Sourcing Plan

Goal of this phase: get all raw ingredients on disk before we touch SQL Server.
Nothing here needs SQL Server yet — just Python.

## The three tiers, and exactly where each one comes from

| Tier | Region(s) | Source | You need to... |
|---|---|---|---|
| 1 — Real | Brazil | Olist Brazilian E-Commerce (Kaggle) | Download manually (login required) |
| 1 — Real | United Kingdom | UCI "Online Retail II" | Download manually (no login) |
| 2 — Synthetic, calibrated | United States, Germany, Ghana | Generated by `generate_synthetic_data.py` | Run a script |
| 3 — Reference | FX rates (BRL, GBP, USD, EUR, GHS) | Free public API | Run a script |

## Step 1 — Create your local project folder

On your own machine (not this chat), open a terminal and run:

```bash
mkdir meridian && cd meridian
mkdir data_generation
cd data_generation
mkdir tier1_raw output
python -m venv venv
# Windows:
venv\Scripts\activate
# Mac/Linux:
source venv/bin/activate
pip install -r requirements.txt
```

Copy the `requirements.txt`, `generate_synthetic_data.py`, `fetch_exchange_rates.py`, and `calibration_reference.json` files (attached below) into this `data_generation/` folder.

## Step 2 — Download Tier 1 real datasets (manual — 10 minutes)

**Olist (Brazil):**
1. Go to `https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce` (free Kaggle account required — sign up if you don't have one, it's free).
2. Click "Download" (downloads a zip, ~45MB).
3. Unzip it into `data_generation/tier1_raw/olist/` — you should end up with files like `olist_orders_dataset.csv`, `olist_order_items_dataset.csv`, `olist_customers_dataset.csv`, `olist_order_reviews_dataset.csv`, etc.

**UCI Online Retail II (UK):**
1. Go to `https://archive.ics.uci.edu/dataset/502/online+retail+ii` (no login needed).
2. Download the `.xlsx` file (it has two sheets: Year 2009-2010, Year 2010-2011).
3. Save it as `data_generation/tier1_raw/online_retail_II.xlsx`.

**Why manual and not scripted?** Kaggle requires authenticated API credentials to download programmatically, and both files need a license-acceptance click-through. Automating this would mean asking you to paste API tokens into a chat, which isn't something I'll do — a two-click manual download is the honest, safe path. (This is worth noting in the README's limitations section later — it's the one non-automated step in an otherwise one-command pipeline.)

## Step 3 — Generate Tier 2 synthetic data (US, Germany, Ghana)

This is `generate_synthetic_data.py`, included below, fully runnable now.

**Calibration approach (read this — it matters for your interview story):**
The script tries to calibrate itself against your real Tier 1 files (avg order value, delivery-time spread) if it finds them in `tier1_raw/`. If it can't find them yet (e.g., you're running this before Step 2), it falls back to *documented placeholder* estimates in `calibration_reference.json`, each one clearly labeled `PLACEHOLDER`. Once you've done Step 2, re-run the script and it will recalibrate against the real numbers — I'll show you the diff when we do that so you can document the "before/after calibration" decision in the data dictionary. This is intentional, not an oversight: it's exactly the kind of "documented judgment call" the project's quality bar asks for.

**Ghana-specific note:** `Faker` (the library) doesn't ship a Ghana locale, so I hand-built a small pool of common Ghanaian first/last names (Akan, Ga, Ewe) and Ghanaian cities, and used GHS (Ghanaian Cedi) as the currency with `+233` phone formatting. This is a simplification versus a proper locale package — worth one line in `DATA_DICTIONARY.md` later.

Run it:
```bash
python generate_synthetic_data.py
```
Output lands in `data_generation/output/`: `us_orders.csv`, `de_orders.csv`, `gh_orders.csv` (plus matching customer files).

## Step 4 — Fetch Tier 3 real FX rates

This is `fetch_exchange_rates.py`, included below.

**API choice — documented decision:** The brief suggested Frankfurter/exchangerate.host. I checked both: Frankfurter is ECB-based and does **not** carry GHS (Ghanaian Cedi isn't in the ECB reference basket), and exchangerate.host now requires a paid API key. Instead I'm using `open.er-api.com` — free, no signup, no key, and it does carry GHS, BRL, GBP, EUR against USD. This is exactly the kind of substitution decision to write into the README later ("swapped X for Y because Z").

Run it:
```bash
python fetch_exchange_rates.py
```
Output: `output/fx_rates.csv`.
